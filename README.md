# Rougelike 隨機地圖生成器

## Proposal Report

### 動機與目標
Rougelike 遊戲對我來說的迷人點在於其過程的不可預測性，以及重複遊玩時每次都有不同體驗。  
本專案目的為設計一款 Rougelike 遊戲的隨機地圖生成器，方便在開發類似遊戲時可以使用，期望能製作一套能穩定生成合理、具挑戰性且不重複之地圖的系統  

### 競品比較
| 比較維度 | 本專案（Godot 隨機路線生成器） | 殺戮尖塔（原版遊戲地圖） | 市售通用地圖插件（Asset Store） |
| :--- | :--- | :--- | :--- |
| **核心目標** | **演算法實作與開源工具化** | 服務於單一遊戲體驗 | 商業化、大眾化 |
| **演算法透明度** | **極高**（專為展示資料結構設計，提供除錯視覺化） | **低**（封裝在遊戲底層，玩家無法得知運作邏輯） | **低**（多為編譯後的黑盒工具 / Black-box） |
| **參數自訂性** | **高**（可自由調整樓層數、節點密度、各類型生成權重） | **無**（數值與規則已寫死） | **高**（但通常伴隨過於複雜的 UI 與學習成本） |
| **圖論驗證機制** | **明確展示**（包含防死胡同、確保連通 Boss 的演算法展示） | 內部隱藏運算 | 通常只保證結果，不展示過程 |
| **引擎依賴性** | **原生 GDScript**（輕量，可直接嵌入任何 Godot 專案） | 無法提取 | 依賴特定版本引擎，有時會造成專案臃腫 |

### 預期功能
參考遊戲《殺戮尖塔》的地圖設計，採用節點式的地圖，給予玩家策略選擇權。
1. 確保地圖路線可行性，防止生成出不合理或無法使用的地圖。
2. 建立節點屬性的分配規則（如：戰鬥、菁英、事件、商店、營地），並能自訂權重，防止生成極端不平衡的路線（例如連續三個營地）。
3. 控制節點分配與路線連接，確保視覺上清晰易讀，不會產生過於混亂的交叉線條。

### 使用技術
預計使用 Godot 當作主要的開發引擎，因為其內建的節點系統非常好用，可以方便快速打樣與實作，也方便視覺化。  
搭配的程式語言是 GDScript，為 Godot 官方的推薦語言。  
核心演算法主要會用到 DAG 的生成，以及在驗證走法時會用到 DFS/BFS 的走訪。

### Prototype 預計可驗證內容
1. 底層邏輯與連通性驗證
- 驗證目標： 確保生成的資料結構符合嚴格的「有向無環圖（DAG）」。
- 可驗證內容：
- - 生成器能穩定輸出不包含迴圈的路線圖，玩家絕對無法走回頭路。
- - 透過DFS演算法，證明底層的每一個「起點」節點，必定存在至少一條路徑能抵達最頂層的「Boss」節點，且圖中沒有任何孤島節點。

2. 視覺化佈局與防交叉驗證
- 驗證目標： 確保抽象的圖論資料能轉換為清晰易讀的使用者介面。
- 可驗證內容：
- - 能在 Godot 畫面上成功繪製出帶有隨機偏移的節點陣列，呈現自然的佈局。
- - 展示「交點最小化」演算法的效果：在多次生成測試中，連接不同節點的線段不會產生嚴重的互相交叉與重疊，維持畫面的整潔。

3. 規則約束與權重驗證
- 驗證目標： 證明演算法能受到自訂規則的有效約束。
- 可驗證內容：
- - 改變輸入參數（例如將「營地」生成機率調高），地圖能即時反應新的機率分佈。
- - 驗證「極端規則防呆」是否生效：例如設定「連續兩層不可出現營地」或「第一層必定是普通戰鬥」，在 Prototype 中連續生成 100 次地圖，皆不會出現違反上述規則的錯誤路線。

4. 基礎互動性驗證
- 驗證目標： 確保資料結構能正確回應玩家的操作。
- 可驗證內容：
- - 玩家點擊某個起點後，系統能正確判定並高亮其「相鄰的下一層節點」。
- - 系統能封鎖無效操作，玩家無法點擊未相連的節點或跳層推進。
