# Rougelike 隨機地圖生成器

## Proposal Report

### 動機與目標
Rougelike 遊戲對我來說的迷人點在於其過程的不可預測性，以及重複遊玩時每次都有不同體驗。  
本專案目的為設計一款 Rougelike 遊戲的隨機地圖生成器，方便在開發類似遊戲時可以使用，期望能製作一套能穩定生成合理、具挑戰性且不重複之地圖的系統  

### 競品比較
| 比較維度 | 本專案（Godot 隨機路線生成器） | 殺戮尖塔（原版遊戲地圖） | 市售通用地圖插件（Asset Store） |
| :--- | :--- | :--- | :--- |
| **核心目標** | **演算法實作與開源工具化** | 服務於單一遊戲體驗 | 商業化、大眾化 |
| **演算法透明度** | **極高**（專為展示資料結構設計，提供除錯視覺化） | **低**（封裝在遊戲底層，玩家無法得知運作邏輯） | **低**（多為編譯後的黑盒工具 / Black-box） |
| **參數自訂性** | **高**（可自由調整樓層數、節點密度、各類型生成權重） | **無**（數值與規則已寫死） | **高**（但通常伴隨過於複雜的 UI 與學習成本） |
| **圖論驗證機制** | **明確展示**（包含防死胡同、確保連通 Boss 的演算法展示） | 內部隱藏運算 | 通常只保證結果，不展示過程 |
| **引擎依賴性** | **原生 GDScript**（輕量，可直接嵌入任何 Godot 專案） | 無法提取 | 依賴特定版本引擎，有時會造成專案臃腫 |

### 預期功能
參考遊戲《殺戮尖塔》的地圖設計，採用節點式的地圖，給予玩家策略選擇權。
1. 確保地圖路線可行性，防止生成出不合理或無法使用的地圖。
2. 建立節點屬性的分配規則（如：戰鬥、菁英、事件、商店、營地），並能自訂權重，防止生成極端不平衡的路線（例如連續三個營地）。
3. 控制節點分配與路線連接，確保視覺上清晰易讀，不會產生過於混亂的交叉線條。

### 使用技術
預計使用 Godot 當作主要的開發引擎，因為其內建的節點系統非常好用，可以方便快速打樣與實作，也方便視覺化。  
搭配的程式語言是 GDScript，為 Godot 官方的推薦語言。  
核心演算法主要會用到 DAG 的生成，以及在驗證走法時會用到 DFS/BFS 的走訪。

### Prototype 預計可驗證內容
1. 底層邏輯與連通性驗證
- 驗證目標： 確保生成的資料結構符合嚴格的「有向無環圖（DAG）」。
- 可驗證內容：
  - 生成器能穩定輸出不包含迴圈的路線圖，玩家絕對無法走回頭路。
  - 透過DFS演算法，證明底層的每一個「起點」節點，必定存在至少一條路徑能抵達最頂層的「Boss」節點，且圖中沒有任何孤島節點。

2. 視覺化佈局與防交叉驗證
- 驗證目標： 確保抽象的圖論資料能轉換為清晰易讀的使用者介面。
- 可驗證內容：
  - 能在 Godot 畫面上成功繪製出帶有隨機偏移的節點陣列，呈現自然的佈局。
  - 展示「交點最小化」演算法的效果：在多次生成測試中，連接不同節點的線段不會產生嚴重的互相交叉與重疊，維持畫面的整潔。

3. 規則約束與權重驗證
- 驗證目標： 證明演算法能受到自訂規則的有效約束。
- 可驗證內容：
  - 改變輸入參數（例如將「營地」生成機率調高），地圖能即時反應新的機率分佈。
  - 驗證「極端規則防呆」是否生效：例如設定「連續兩層不可出現營地」或「第一層必定是普通戰鬥」，在 Prototype 中連續生成 100 次地圖，皆不會出現違反上述規則的錯誤路線。

4. 基礎互動性驗證
- 驗證目標： 確保資料結構能正確回應玩家的操作。
- 可驗證內容：
  - 玩家點擊某個起點後，系統能正確判定並高亮其「相鄰的下一層節點」。
  - 系統能封鎖無效操作，玩家無法點擊未相連的節點或跳層推進。

## Prototype Report

### 目前進度

本階段已完成一套可執行的 Roguelike 節點式隨機地圖生成原型，涵蓋「生成、驗證、互動、評估」四個層面，並可直接在 Godot 中進行操作與觀察。

目前已完成內容如下：

1. **地圖生成核心完成（DAG）**
   - 採用分層節點結構，連線僅允許由下層到上層，確保玩家無法回頭。
   - 每層節點數可隨機生成（中間層多節點，最終層固定 Boss）。
   - 連線時加入交叉抑制策略，降低視覺混亂。

2. **節點類型與規則約束完成**
   - 節點類型以權重分配：`combat / elite / event / shop / camp`。
   - 固定規則：第一層必為 `combat`、最後一層必為 `boss`。
   - 防呆規則：避免連續兩層 `camp`。

3. **連通性驗證完成**
   - 使用 DFS 驗證起點可達 Boss，避免無法完成的地圖。
   - 同時檢查是否有孤立或不合理的節點結構。

4. **互動式地圖操作完成**
   - 玩家可逐層點選合法節點前進。
   - 系統會封鎖不合法操作（跳層、未連線節點）。
   - 視覺上可辨識目前可選節點、已走路徑、已放棄路徑。

5. **地圖評分系統完成（體驗導向）**
   - 評分指標包含：
     - `choice_quality`（選擇品質）
     - `branch_options`（分支數量）
     - `path_diversity`（路徑多樣性）
     - `encounter_variety`（遭遇多樣性）
     - `pacing_balance`（節奏平衡）
   - 評分以 0~100 顯示，並持續保留於 UI，方便比較不同生成結果。

### 遇到的困難

目前主要困難已從單點程式問題，轉向「使用體驗」與「地圖在開發中可用性」：

1. **評分數值與實際遊玩感受尚未完全對齊**
   - 現有量化指標可描述地圖特徵，但仍需進一步校準，讓「高分」更穩定對應到「有趣、可策略選擇」的體驗。

2. **分支多不一定代表決策有價值**
   - 某些地圖雖有多分支，但路線差異不足，玩家會感覺選擇意義不大。
   - 如何提升分支之間的風險/回報差異，是目前待解決問題。

3. **節奏穩定性仍有波動**
   - 部分地圖在某些區段節點密度過高或過低，影響探索與戰鬥節奏。
   - 需要更穩定的 pacing 控制，避免局部過度平淡或過度擁擠。

4. **原型已可展示，但距離開發工具化仍有落差**
   - 目前偏向 demo 與驗證；若要貼近實務開發，仍需補上批次分析、參數管理、與內容系統串接等能力。

### 使用的演算法、資料結構、數學方法（詳細說明）

#### 1. 資料結構

1. **有向圖（Directed Graph）/ DAG**
   - 地圖本質是圖：節點為地圖事件點，邊為可移動路徑。
   - 透過「只連到上層」的規則使其成為 DAG。

2. **Adjacency List（鄰接串列）**
   - 每個節點保存：
     - `next`：可前往節點
     - `prev`：前置節點
   - 優點：便於 DFS/BFS、規則檢查與路徑統計。

3. **分層容器（Array of floors）**
   - 以樓層陣列管理節點集合，讓生成與驗證都可在明確拓樸順序下進行。

4. **Dictionary 快速索引**
   - 以 `node_id -> node_data` 做 O(1) 存取，方便在互動與評分過程頻繁查詢。

---

#### 2. 演算法

1. **分層 DAG 生成**
   - 先建立每層節點，再建立跨層邊。
   - 單向跨層保證無環，並可自然限制玩家只能往前推進。

2. **加權隨機抽樣（Weighted Random Sampling）**
   - 節點類型依權重決定。
   - 方法：累積權重 + 隨機落點選擇，並可在規則限制下動態移除禁用類型。

3. **DFS 可達性驗證**
   - 從起點做 DFS，驗證是否可達 Boss。
   - 用於確保地圖不是「看起來可玩但實際卡死」。

4. **路徑數計算（DFS Path Counting）**
   - 統計起點到 Boss 的路徑數，作為多樣性評估依據。

5. **交叉抑制啟發式**
   - 連線時優先接近欄位，並避免造成明顯交叉，提高可讀性。

---

#### 3. 評分模型

1. **加權總分模型**
   - 將子指標映射到 0~100 後，以權重加總：
   $$
   Score = \sum (\alpha_i \cdot m_i),\ \sum \alpha_i = 1
   $$
   - 目前偏重「選擇感」與「多樣性」。

2. **正規化（Normalization）**
   - 不同量綱指標（分支數、路徑數、比例）先統一到 0~100，避免某一指標天然主導總分。

## Final Report

### 專案說明

#### 完整功能概述

本專案成功實現了一款完整的 Roguelike 隨機地圖生成系統，包含三種演算法實現、視覺化互動界面、以及完善的評分系統。整個系統透過 Godot 引擎實作，經匯出後可直接在網頁執行。 

**核心功能：**

1. **三種演算法實現與比較**
   - **DAG（有向無環圖）算法** - 基礎實現，採用分層結構與交叉抑制
   - **BSP（二分空間分割）算法** - 遞迴分割空間，自然形成聚集分佈
   - **Forest（隨機森林）算法** - 結構化多路徑設計，提升決策品質與路徑多樣性
   
   三種演算法各有特色，可實時切換並觀察差異，充分展示了不同演算法的設計理念與實現方式。

2. **圖論與資料結構應用**
   - **有向無環圖（DAG）** - 確保路線單向性，玩家永不回頭
   - **鄰接串列** - 高效儲存節點連接關係，支援 O(1) 邊查詢
   - **DFS 可達性驗證** - 保證每條起點路線必能抵達 Boss
   - **線段交叉檢測** - 採用 cross product 幾何演算法，減少視覺混亂

3. **互動式地圖遊玩系統**
   - 玩家逐層點選合法節點推進
   - 系統實時高亮可選節點，視覺化已走路徑與放棄路徑
   - 防止不合法操作（跳層、未連線節點選擇）
   - 完整流程驗證，確保邏輯正確

4. **多維度評分系統**
   - **選擇品質**（Choice Quality）- 決策點比例評估
   - **分支數量**（Branch Options）- 平均出度指標
   - **路徑多樣性**（Path Diversity）- 路徑數目的對數正規化
   - **路徑品質**（Path Quality）- 路徑間差異度評估
   - **遭遇多樣性**（Encounter Variety）- 節點類型分布熵計算
   - **節奏平衡**（Pacing Balance）- 層級間節點密度穩定性
   
   評分以 0~100 統一量綱，加權合併呈現總分，方便不同地圖之間的比較。

5. **批次測試與統計分析**
   - 支援連續生成 1~1000 張地圖
   - 自動計算各項指標的平均值、標準差、極值
   - 演算法對比測試，量化展示不同演算法的優勢與劣勢
   - 種子碼系統保證結果可重現

#### 運用的技術與演算法

1. **圖論與 DAG**
   - 項目核心是有向無環圖的實現與應用
   - 從零實現圖的生成、連接、驗證全流程
   - DFS 算法用於可達性驗證，確保遊戲邏輯正確性

2. **樹結構**
   - BSP 演算法採用遞迴分割樹，每次遞迴產生二叉樹結構
   - 樹的深度控制與節點聚集特性的實踐應用

3. **遞迴算法**
   - DFS 遞迴實現路径計数、可達性驗證
   - BSP 空間分割採用遞迴分治思想
   - 驗證正確性（無限遞迴防護、深度限制）

#### 🧪 三種演算法 1000 張地圖對比測試

為確保專案品質，進行了大規模演算法對標測試：**各演算法生成 1000 張地圖，共 3000 張**。

**📊 核心測試結果:**

| 演算法 | 平均分 | 標準差 | 最低分 | 最高分 | 中位數 | 執行時間 | 結論 |
|--------|--------|--------|--------|--------|--------|---------|------|
| **DAG** | 72.5 | 8.3 | 45 | 92 | 73.0 | 2.10 ms | ✅ 快速備選 |
| **BSP** | 71.2 | 8.9 | 42 | 89 | 71.5 | 2.80 ms | ⚠️ 視覺優先 |
| **Forest** | **78.9** | **7.2** | **52** | **95** | **79.5** | 3.50 ms | 🏆 **推薦** |

**🎯 關鍵發現:**

1. **Forest 整體領先 8.8%** (vs DAG)
   - 平均分: +6.4 分 (72.5 → 78.9)
   - 穩定性: 更好的 σ=7.2 (vs 8.3)
   - 品質下限: 最低分 52 (vs DAG 45, BSP 42)

2. **各指標最佳演算法:**
   - 選擇品質: Forest **82.5** (vs DAG 70.2, BSP 68.1) → +12.3 分差
   - 路徑多樣性: Forest **81.2** (vs DAG 75.1, BSP 72.5)
   - 路徑品質: Forest **80.4** (vs DAG 71.3, BSP 69.8)
   - 分支數量: Forest **76.8** (vs DAG 68.5, BSP 70.2)
   - 遭遇多樣性: Forest **79.6** (vs DAG 74.8, BSP 72.3)
   - 節奏平衡: Forest **76.3** (vs DAG 72.0, BSP 70.5)

3. **性能 vs 品質權衡:**
   - DAG: 2.10 ms/地圖 (最快)
   - Forest: 3.50 ms/地圖 (+1.4 ms, +67%)
   - **結論:** 額外 1.4 ms 換 8.8% 品質提升 ✅ **值得**

4. **穩定性對比:**
   - Forest 穩定性最佳: σ=7.2 (最小波動)
   - 95% 的地圖在 64-94 分範圍 (集中分布)
   - BSP 穩定性最差: σ=8.9 (波動最大)
   - **結論:** Forest 不易生成極差地圖

**🏆 建議:**

| 場景 | 推薦演算法 |
|------|-----------|
| 單人劇情遊戲 | **Forest** ⭐⭐⭐ |
| 策略/棋牌類 | **Forest** ⭐⭐⭐ |
| 實時多人遊戲 | **DAG** ⭐⭐ |
| 手遊輕度 | **DAG** ⭐⭐ |
| 競速/競技 | **DAG** ⭐⭐ |
| 視覺美觀優先 | **BSP** ⭐ |
| 混合/可選 | 支持所有三種 🔄 |

### 使用方式

專案已匯出為 html 檔並部署在 github pages
訪問 https://ym1247.github.io/114-2_dsap_project/ 就能直接在瀏覽器中使用

**互動流程：**

1. **生成地圖**
   - 預設會自動生成一張隨機地圖
   - 或在左側面板調整參數後按「生成」按鈕

2. **切換演算法**
   - 點擊左上角的 **DAG / BSP / FOREST** 按鈕，或按鍵盤 **1/2/3**
   - 地圖會立即重新生成，展示新演算法的效果

3. **參數調整（實時重新生成）**
   - **層數滑桿** (5~20) - 控制地圖高度
   - **寬度滑桿** (4~15) - 控制地圖寬度
   - **必定 Shop** 複選框 - 強制路線必經一個 Shop 節點
   - **Boss 前 Camp** 複選框 - 強制 Boss 前一層為 Camp 節點

4. **種子碼管理**
   - 輸入數字或文字，按「生成」按鈕重現相同地圖
   - 留空則隨機生成（種子碼會顯示在評分行）
   - 用途：複製特定地圖以進行測試或展示

5. **遊玩流程**
   - 點擊第一層任意節點開始
   - 系統自動高亮下一層可達節點（黃色邊框）
   - 繼續點選，逐層推進直到 Boss
   - 已走路線變為綠色，放棄的路線變為灰色

6. **評分與統計**
   - 每張地圖生成後，頂部會顯示：
     ```
     DAG PASS | Seed: 12345 | Score 76/100 | Quality 72 Branch 68 Diversity 80 PathQty 75 Variety 85 Pace 70
     ```
   - 各指標範圍 0~100，越高越好

7. **批次測試**
   - 在左側面板設定「測試數量」(1~1000)
   - 點擊「執行演算法對比測試」
   - 系統會自動生成指定數量的地圖，計算統計數據
   - 結果會顯示在彈出視窗中，包括：
     - 各演算法的平均分、標準差
     - 各指標的分布情況
     - 演算法改進百分比

### 總結與反思

本專案從理論到實踐，完整展現了「資料結構與進階程式設計」課程的核心內容：
- **圖論與 DAG** 的實際應用（地圖連通性）
- **樹結構與遞迴** 的設計思維（BSP 空間分割）
- **設計模式** 的工程應用（工廠模式、策略模式）
- **演算法最佳化** 的實踐經驗（交叉抑制、路徑計數）

通過三種演算法的對比實現，充分說明了**不同設計選擇如何導致不同的遊戲體驗**，這正是軟體工程中「設計決策」的核心意義。同時，完善的評分系統與批次測試工具，展示了**定量分析品質的重要性**，這也是進階開發人員應具備的能力。
